# v1.3.0

Feature release. Focus: when a lease is deleted because its egress is unusable,
record a persistent penalty against that one node so the allocator stops
preferring it.

## Feature

- Deleting a lease now records a penalty on the node the lease was bound to,
  keyed strictly by `node_hash`. The penalty is graded and time-decayed: each
  deletion adds `1` unit worth `500ms` of equivalent latency, decaying with a
  `6h` half-life. The allocator's `P2C` score (`calculateScore`) adds the decayed
  penalty in the same nanosecond-latency dimension as the policy score, so a
  penalised node loses comparisons against its peers but is never hard-excluded
  — no single direction ratchet can pin a node to the bottom of the ranking.
- The penalty is deliberately **not** stored in `FailureCount`. Passive health
  treats a fully transferred response as a network success even for 5xx, and the
  probe loop visits every node including circuit-open ones against a target that
  remains reachable from a blocked egress — so a failure-count-based penalty
  would be reset by the next probe cycle and would never survive.
- Scoped to a single node: nodes sharing the same egress IP are left untouched.
  A penalty must never spread by IP.

## Operational

- `RESIN_LEASE_PENALTY=0` disables the feature entirely; unset or any other
  value keeps it enabled. No rollback of the binary is needed to turn it off.
- No new configuration fields were introduced; the feature adds no request
  volume and does not touch the proxy hot path beyond one float64 addition in
  the existing score computation.

## Notes

- `nodes_dynamic` gains `penalty_units` and `penalty_updated_at_ns`
  (`000003_node_penalty`). Both are added with `DEFAULT 0`, so an existing
  `cache.db` upgrades in place.
- Persistence is driven by the engine's dirty set, so `ApplyNodePenalty`
  notifies `OnNodeDynamicChanged` like `RecordResult` does. Without that
  notification the penalty would live in memory only and be lost on restart.
