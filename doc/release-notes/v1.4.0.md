# v1.4.0

Feature release. Focus: make the probe answer "can this node serve the business
request right now" instead of "did something answer". Also lets an operator
change the probe request itself at runtime, without a rebuild.

## Feature

- Probe judgement is now three layers instead of one:
  - `probe_reject_status_codes` (default `403, 429, 500, 502, 503, 504`) — a
    gate answering 403/5xx is a failed probe, not a healthy one.
  - `probe_reject_body_substrings` — catches gates that answer `200` with an
    error document in the body. Matching is case-insensitive.
  - `probe_request` — method, body and headers for the probe, so it can replay
    the real business request instead of `GET /`.
- Probe scripts (opt-in, `probe_script_enabled`, default off). Two JavaScript
  snippets, executed in an embedded engine (goja, pure Go, no cgo):
  - `probe_script_build` returns `{url, method, headers, body}` for the probe.
    It owns the target URL as well — a script that could only change headers
    would still hit the old endpoint.
  - `probe_script_judge` receives `(ctx, statusCode, body)` and returns
    `{ok, reason}`. A rejection is recorded as a probe failure, so it feeds the
    normal circuit-breaker path.
  - Scripts are validated at save time: a syntax error is rejected with `400`
    and the offending field named, instead of being persisted and silently
    falling back to default behaviour at runtime.
- Script binary limits: 16 KB per script, methods restricted to `GET`/`HEAD`/
  `POST`, no `require`/`process`/`fetch`/`module`/`XMLHttpRequest`, and a hard
  timeout so a runaway loop cannot wedge the probe loop.

## Operational

- The egress probe is never rewritten. It still issues the plain
  `cloudflare.com/cdn-cgi/trace` GET, because that body is how the node's egress
  IP is learned; only the latency probe replays the operator request.
- A broken or timed-out script falls back to the declarative template rather
  than taking health checking offline.
- Config rows written by older versions adopt the new defaults on load
  (`ApplyMissingDefaults`). An explicitly stored empty list is preserved, so
  `"probe_reject_status_codes": []` stays a deliberate "disable this rule".

## Notes

- `probe_reject_status_codes` is the rollback switch: clearing it restores the
  previous "any response is healthy" behaviour without downgrading the binary.
- Expect the healthy-node count to drop at first. On a pool where most nodes are
  gated, the rule promotes nodes that were previously counted healthy on a
  200 from a page that no business request can use.
- Existing `cache.db` and `state.db` upgrade in place; no migration is required.
