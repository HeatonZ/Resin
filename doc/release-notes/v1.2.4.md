# v1.2.4

Performance release. Focus: removing amplification around latency sampling on
large node pools (thousands of nodes) so CPU cost per unit of probe traffic
drops.

## Performance

- Platform re-evaluations are now coalesced and drained by a single background
  worker instead of blocking the caller. Probe workers and passive
  request-path health feedback used to wait on every platform's view lock for
  each probe result; they now enqueue and return. Notifications are never
  dropped: when the queue is saturated the caller applies inline, and the
  latency-filtered variant still only touches platforms with
  `MaxReferenceLatencyMs > 0` (the v1.2.3 optimisation is preserved).
- Per-node subscription IDs are published copy-on-write. The periodic scan and
  tag matching no longer take a read lock and allocate a fresh slice per node
  on every pass.
- Per-domain latency table reads take a read lock instead of the write lock,
  and refresh `lastAccessNs` atomically. Routing reads no longer serialise
  against each other or against latency writers on the same node.

## Notes

- `GlobalNodePool` now owns a dirty-notification drainer
  (`StartPlatformDirtyWorker` / `ClosePlatformDirtyWorker`). It starts before
  the probe manager and stops after it, so shutdown flushes what is queued.
- `FlushPlatformDirty()` is available for callers that must observe platform
  views deterministically right after a mutation. Production request and probe
  paths do not call it; they accept eventual consistency.
- Behaviour is unchanged from the caller's point of view: routable views still
  reflect node health, egress region, and latency samples. The only difference
  is *when* the update lands (immediately under light load, microseconds to
  milliseconds later under probe bursts).
