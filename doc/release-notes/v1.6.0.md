# v1.6.0

## 探针脚本可以携带真实凭据

上一版的脚本引擎能改请求，但沙箱里拿不到任何凭据，所以它发出去的仍然是一个
"没有身份"的请求——而这恰好就是它要检测的那个问题。

现在脚本通过 `ctx.env.<name>` 读取凭据，凭据来自容器环境变量：

```
-e RESIN_PROBE_SECRET_APIKEY=sk-xxxx
```

脚本里 `ctx.env.apikey` 即可取到（变量名后缀自动转小写）。

## 凭据不会泄露

这是本次改动最需要保证的性质。凭据字段带 `json:"-"`：

- `GET /api/v1/system/config` 不返回，也不返回字段名
- PATCH 响应不回显
- 不写进 `state.db`，数据库二进制里搜不到明文
- 日志不打印值，启动时只打印"加载了 N 个"

代价是它不持久化：**每次启动必须重新从环境变量注入**，重启后不会自动恢复。
这是有意的取舍——凭据放进可序列化的配置里，就等于同时放进了 API 响应和数据库。

## 同时修复：脚本的 User-Agent 被覆盖

`outbound_http.go` 在设置完脚本头之后，又无条件 `Set("User-Agent", "Resin/1.0")`，
把脚本写的客户端标识覆盖掉了。上游正是靠这个头判断客户端身份的，所以这个 bug
会让带凭据的探针看起来仍然"没有身份"。

修复后脚本提供的 UA 优先，且比较大小写不敏感（脚本可能写 `user-agent`）。

## 验证

本机 Docker 端到端，测试台记录真实发出的请求：

- 凭据送达脚本：`Authorization` 含真实 secret，长度匹配
- 请求形状与 oc2api 一致：UA `opencode/1.18.31 ai-sdk/provider-utils/4.0.23 runtime/bun/1.3.13`、
  `x-opencode-client: desktop`、`x-opencode-project: global`、`x-opencode-session: ses_...`
- 打「出口被封」端点（403 + `abusive traffic`）→ judge 判失败，`failure_count` 0 → 1
- 打好端点（200）→ 通过，`failure_count` 保持 0
- 热更新无关配置后凭据仍在（deep-copy 没有丢 map）
- 泄露复检：API 响应 0 处、容器日志 0 处、`state.db` 二进制 0 处

`go test ./...` 16 个包通过，两条既有失败与本次改动无关。

## 使用方式

```bash
# 1. 注入凭据
docker run ... -e RESIN_PROBE_SECRET_APIKEY=sk-xxxx ...

# 2. 下发脚本（示例见 probe-script-with-credentials.js）
PATCH /api/v1/system/config
{
  "probe_script_enabled": true,
  "probe_reject_only_unreachable": false,
  "probe_script_build": "...",
  "probe_script_judge": "..."
}
```

注意 `probe_reject_only_unreachable` 要关掉，否则 judge 脚本会被跳过。
