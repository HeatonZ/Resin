# v1.7.1

## 选路从 2 个候选扩到 3 个

一次租约分配原来只随机抽 2 个节点做 P2C 比较，两个都不好就只能挑相对好的那个。
现在默认抽 3 个（`RESIN_P2C_CANDIDATES`，范围 1–16，设 2 即回到旧行为，重启生效）。

打分维度没变，仍是 `(同出口 IP 租约数 + 1) × 延迟 + 删租约惩罚`，只是多了
一次"再抽一个看看"的机会。三分支延迟比较逻辑与旧的两两比较一致：

1. 候选都有目标域名的新鲜延迟 → 用目标域名延迟
2. 否则取所有候选都有的 authority 域名延迟均值
3. 都没有 → 延迟按 0 处理，退化为按负载打分

## 为什么值得改：实测数据

拿现网 cache.db（763 个合格节点、544 个带删租约惩罚）跑真实代码 2 万次分配：

- 2 候选：平均选中延迟 251ms，落到带惩罚节点的比例 58.8%
- 3 候选：平均选中延迟 228ms（**−9%**），带惩罚节点 52.8%（**−6.0 个百分点**）
- 4 候选：209ms / 48.7%
- 6 候选：181ms / 44.3%

收益递减很明显，3 是性价比拐点。代价是每次分配多一次抽样和一次打分，
`internal/routing` 全量测试仍在 1 秒内跑完。

## 说清楚它不解决什么

这不是"降权"，是"更容易被比下去"。删除租约只给节点记 +1 单位惩罚
（500ms 等效延迟，半衰期 6 小时），而现网 71% 的节点都带惩罚——靠加分数
永远清不干净。要真正降权需要改抽样方式或做视图硬排除，不在本版范围内。

副作用：选路更偏爱低延迟节点，47 条租约用到的不同出口 IP 从 42.4 个降到
41.0 个，可以忽略。

## 回滚

```
RESIN_P2C_CANDIDATES=2
```

容器环境变量设上后重启即回到 v1.7.0 的两两比较行为，不需要换镜像。
